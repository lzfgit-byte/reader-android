# ADR-0012：正文接受任意 HTML，但必须清洗并转为结构块

## 状态

`approved`

## 背景

文本阅读（F27）最初只接受规范化段落块（`TextBlock[]`），理由是安全、UI 简单。实际使用中这会把成本转嫁给配置作者：几乎所有来源的正文都是 HTML，作者必须在脚本里手写 DOM 遍历去拼块。

现决定（原开放问题 Q13）：**接受任意 HTML**，同时**增加 HTML 安全校验过滤**。

## 备选方案

| 方案 | 说明 | 取舍 |
|---|---|---|
| A. 只收结构块 | 配置作者负责转换 | 最安全，但脚本成本高、易漏（表格/列表/引用要逐个处理） |
| B. 收 HTML 直接渲染 | 用 WebView 或富文本组件直接显示 | 最省事，但**执行任意 HTML = 执行任意脚本**，且样式会污染阅读器排版 |
| C. 收 HTML → 清洗 → 转结构块 → 渲染 | 引擎做一次白名单过滤与结构归一 | 作者门槛低、UI 仍只吃结构块、安全可控 |

## 决策

采用 **方案 C**：

1. `getTextContent` 可返回 `{ html }`、`{ blocks }`，或两者都给（`blocks` 优先）；
2. 若给 `html`，引擎执行 **HTMLSanitizer**：
   - **标签白名单**：`p` `br` `h1`–`h4` `blockquote` `ul` `ol` `li` `strong` `em` `u` `s` `code` `pre` `a` `img` `hr` `table` `thead` `tbody` `tr` `th` `td` `figure` `figcaption`
   - **属性白名单**：`a[href]`、`img[src]`、`img[alt]`、`*[class]`（仅用于排版提示，不参与样式）；
   - **删除整棵子树**：`script` `style` `iframe` `object` `embed` `form` `input` `button` `svg` `canvas`、所有 `on*` 事件属性；
   - **URL 白名单**：`http` `https` `data:image/`；`javascript:` `vbscript:` `file:` 一律丢弃；
   - **样式**：丢弃所有 `style` 属性与 `<style>`，排版完全由阅读器设置决定；
3. 清洗后**转换为 `TextBlock[]`**（`p` / `h2` / `h3` / `quote` / `list` / `image` / `code` / `table`），UI 永远只渲染结构块；
4. 限制：单章 HTML ≤ 2MB；清洗后无有效内容时按空章节处理（提示"该章无正文"），不报致命错误。

## 理由

1. **降门槛**：来源的正文本来就是 HTML，让作者直接给 HTML 是最省力、最不容易漏的做法。
2. **安全边界清晰**：白名单 + 结构归一之后，UI 面对的是受控数据，不存在"渲染任意 HTML"的执行面。
3. **排版一致**：丢弃来源样式，所有内容用同一套阅读器排版，避免每章字体/行距/底色花掉。
4. **结构块仍是唯一出口**：清洗只发生在引擎内部，`TextReaderScreen` 的实现不必为两种输入写两套逻辑。

## 后果

**正面**

- 配置作者可直接 `return { html: doc.innerHTML }`
- UI 与渲染保持受控，无脚本执行面
- 排版统一

**负面（必须正视）**

- 需要维护 sanitizer（白名单随来源变化可能需要补充标签）
- 会丢失来源的精细样式（如脚注、复杂表格布局），属可接受折损
- HTML→块转换是有损的，特殊结构可能退化为纯段落
- 2MB 限制对超长单章可能触发，需要提示与分章建议

## 缓解

- sanitizer 与转换器独立成 `:core:engine` 内的组件，配单测样本（恶意 HTML 用例集）
- 未被识别的标签降级为 `p` 保留文本，而不是整块丢弃
- 调试台可直接看到清洗后的 `blocks`，便于作者判断"哪些结构被折叠了"
