# ADR-0011：移除远程服务模式，只保留内置引擎

## 状态

`approved`

## 背景

[ADR-0002](ADR-0002-embedded-engine-dual-provider.md) 当时选择"内置引擎 + 远程服务"双模式，理由是：多设备共享、可测试性、契约先行。

现在明确：**不保留远程服务模式**（原开放问题 Q8）。

这意味着以下能力整体移出范围：`RemoteRepository`、WebSocket 日志客户端、多服务端配置（原 F18）、远程地址与连通性测试。

## 备选方案

| 方案 | 说明 | 取舍 |
|---|---|---|
| A. 保留双模式 | 维持 ADR-0002 | 多设备共享，但要维护两套实现、两倍测试矩阵、一份长期契约 |
| B. 只保留内置引擎 | 单模式 | 实现与测试减半；失去共享能力 |
| C. 只保留远程 | 引擎外置 | 违背单机自足（P1），且手机端将无法离线可用 |

## 决策

采用 **方案 B：只保留内置引擎**。

1. 删除 `RemoteRepository`、远程地址设置、WebSocket 日志客户端、多服务端（`F18` 置为 `dropped`）；
2. 数据层只剩一条路径：UI → `GhsRepository` → `LocalRepository` → 内置引擎 + 本地仓库；
3. **保留 `/engine/**` 本地出口**（默认关闭）：它服务于调试、外部工具与自动化回归，不属于"远程服务模式"；
4. `rest-contract.md` 降级为「内核 API 契约」，描述 `/engine` 暴露的方法与字段。

## 理由

1. **需求不存在**：用户明确不需要多设备共享；为不存在的需求付两套实现的成本不合理。
2. **测试矩阵减半**：双模式下每条链路要在两种实现上各跑一遍，单模式下只需保证一条。
3. **可测试性已由 `/engine` 满足**：用 `curl` 或脚本驱动本机引擎的能力与远程模式无关，一个本地出口就够。
4. **减少设置项**：数据源模式、远程地址、连通性测试三项直接消失，设置页更简单（也与 Q12 的"App 端最小化"一致）。

## 后果

**正面**

- 数据层实现与测试减半
- 设置页与文档更简单
- 少一个长期契约的维护方

**负面（必须正视）**

- **失去多设备共享**：同一份配置与进度无法在手机和另一台设备间实时看齐；替代方案是 WebDAV 备份/恢复（F20/F26）
- 已写的远程相关设计（`§8` 差异表、`RemoteRepository`）需同步清理，避免文档残留
- `/engine` 出口虽然保留，但**不再有"同一份契约被两个实现验证"的保障**，契约与实现的一致性只能靠单测

## 缓解

- `rest-contract` 与 `LocalRepository` 的方法一一对应，用契约测试保证不漂移
- 跨设备需求用 WebDAV 同步（配置/进度/收藏/历史）覆盖，不做实时一致性
